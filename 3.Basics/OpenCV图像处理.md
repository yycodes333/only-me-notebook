## 3.4.3 常用术语

在正式开启OpenCV图像处理相关学习之前，我们需要在这里补充一些常用术语和概念的解释，要不再讲解时候会涉及到很多的知识，对于初学者，学习阻碍很大。

### 3.4.3.1 像素

在计算机中，图像本质上是一个由数字组成的矩阵。一张图片看起来是连续的画面，但计算机并不能直接理解“画面”，它只能处理数字。因此，图像会被拆分成一个个小方格，每个小方格称为 **像素（Pixel）**。

每个像素记录了该位置的颜色或亮度信息，是图像中最小的显示单位。

例如，一张灰度图可以理解为：

```text
[
  [  0,  30,  80, 120],
  [ 20,  60, 100, 150],
  [ 50,  90, 180, 220],
  [100, 160, 200, 255]
]
```

其中每个数字表示一个像素的亮度，在这里灰度图也就是表示灰度的亮度程度。

一张图片由大量像素组成。

例如：

```text
宽度 = 1920
高度 = 1080
```

表示这张图像：

- 横向有 1920 个像素
- 纵向有 1080 个像素
- 总像素数为：1920 × 1080 = 2,073,600

常见情况下，像素值范围是：

```text
0 ~ 255
```

其中：

| 像素值 | 含义                     |
| ------ | ------------------------ |
| 0      | 最暗                     |
| 255    | 最亮                     |
| 中间值 | 不同程度的亮度或颜色强度 |





### 3.4.3.1 常见图像类型

#### 彩色图

**彩色图**，（`Color Image`）是一种由红、绿、蓝三通道构成的图像，由一个三维矩阵构成，形状一般为（H，W，C）。

最常见的是 RGB 彩色图，由三个通道组成即、绿、蓝组成，每个像素由三个数值共同表示颜色，分别对应通道颜色的强度，比如在R通道，当像素是255这里表示满红，红色强度最大了，当R通道像素为0表示没有红色，红色强度最小，当每个通道都是255表示白色，每个通道都是0,表示黑色。

```
R 通道：记录红色强度
G 通道：记录绿色强度
B 通道：记录蓝色强度
```

> 注意：**OpenCV里默认使用BGR彩色图**。

#### 灰度图

**灰度图**，（`Grayscale Image`），是一种只有灰色亮度信息、没有颜色信息的图像，即每个像素只有一个灰度值，一般由二维矩阵构成，形状一般是（H，W）。

灰度图中的每个像素通常只有一个数值，用来表示灰色亮度的亮暗程度。

常见范围为0~255,其中，0表示黑色，255表示白色，自1-254表示不同程度的灰色，即0-255表示从黑-->暗灰-->浅灰-->白。

#### 二值图

**二值图**，`Binary Image`，是一种只有两个取值的图像，一般也是由二维矩阵构成，形状为（H，W）。

像素表示范围只有0和255，其中0表示就是前景，255表示背景。

当你读到前景和背景时候又懵了吧，别慌，在后面我们会做到介绍，现在简单理解成，前景一般就是我们需要的目标区域的内容，背景就是相反不是目标的区域，你现在有个印象就行了。

#### 原始图

在图像处理中，**原始图**通常指未经处理或刚读取进来的图像。他可以是我们之前说过的灰度图、RGB彩色图、BGR彩色图也可以是带`Alpha`通道的图像和相机传感采集的RAW图像。

在这里可能你又不懂了，什么叫做带Alpha`通道的图像。

所谓Alpha指的是透明度，一般我们从网上下载JPG格式的图片可能只有BGR三通道，但对于Png格式或者是Tiff格式的图像原始来讲是由透明度即一般形状是BGRA。

Alpha通道的取值范围也是0~255，其中0表示完全透明，255表示完全不透明，对于1-254均表示半透明。

在教程中，如果没有特别说明，原始图一般指：从文件或相机中读取后，尚未进行预处理的图像。



### 3.4.2.x RGB & BGR & GRAY & HSV及互相转换

BGR 和 RGB 本质上使用的是同样的三个颜色通道，只是通道顺序不同。在我们处理图像过程中，必须要注意的是，何时的通道是RGB何时的通道是BGR，这里我们作以区分。

RGB一般应用于：深度学习模型输入、Pillow 读取图像、Matplotlib 显示图像、大多数图像标注工具、Web 图像、屏幕显示，即大部分情况下彩色图使用的通道格式就是RGB。

BGR一般应用于：OpenCV图像处理，比如，在 OpenCV 中，使用 `cv2.imread()` 读取图片时，默认得到的是 BGR 格式。

既然涉及到不同场景下使用，我们会涉及到RGB和BGR的切换即需要转换彩色图的通道格式，采用OpenCV库内置函数`cv2.cvtColor`即可实现，具体如下展示：

1）BGR转RGB

```python
img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB)
```

2）RGB转BGR

```python
img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_RGB2BGR)
```



除了以上OpenCV内置方法`cv2.cvtColor`实现转换也可以通过NumPy实现：

```
img_rgb = img_bgr[:, :, ::-1]
img_bgr = img_rgb[:, :, ::-1]
```

## 3.4 GRAY

### 3.4.1 什么是 GRAY？

GRAY 表示灰度颜色空间。

灰度图没有颜色信息，只有亮度信息。

在 OpenCV 中可以通过下面方式转换：

```python
gray = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2GRAY)
```

---

### 3.4.2 RGB 转灰度的基本思想

灰度图并不是简单地把 R、G、B 三个值相加再平均。

因为人眼对不同颜色的敏感程度不同：

```text
人眼对绿色最敏感
其次是红色
对蓝色相对不敏感
```

常见灰度转换公式为：

```text
Gray = 0.299 × R + 0.587 × G + 0.114 × B
```

因此绿色通道在灰度转换中权重最大。

---

### 3.4.3 GRAY 的应用场景

GRAY 常用于：

- 边缘检测
- 角点检测
- 轮廓提取
- 阈值分割
- 模板匹配
- 文字识别预处理

---

## 3.5 HSV

### 3.5.1 什么是 HSV？

HSV 是另一种常见颜色空间，它更接近人类描述颜色的方式。

HSV 包含三个分量：

```text
H：Hue，色相
S：Saturation，饱和度
V：Value，明度
```

---

### 3.5.2 HSV 三个分量的含义

| 分量 | 中文名 | 含义                             |
| ---- | ------ | -------------------------------- |
| H    | 色相   | 表示颜色类型，例如红、黄、绿、蓝 |
| S    | 饱和度 | 表示颜色纯度，越高越鲜艳         |
| V    | 明度   | 表示颜色亮度，越高越亮           |

---

### 3.5.3 HSV 为什么常用于颜色分割？

在 RGB 空间中，颜色和亮度混合在一起。

例如同一个红色物体，在不同光照下 RGB 值可能差异很大：

```text
强光下：RGB = [255, 80, 80]
弱光下：RGB = [120, 30, 30]
```

虽然它们看起来都是红色，但 RGB 数值差异明显。

而 HSV 将颜色信息和亮度信息相对分离：

```text
H 主要表示颜色类别
S 表示颜色纯度
V 表示亮度
```

因此在做颜色识别时，HSV 往往比 RGB 更稳定。

---

### 3.5.4 HSV 的应用场景

HSV 常用于：

- 颜色检测
- 颜色分割
- 交通灯识别
- 皮肤区域检测
- 特定颜色物体提取
- 图像增强
- 光照变化较大的场景

---

### 3.5.5 OpenCV 中 HSV 的范围

需要特别注意，OpenCV 中 HSV 的取值范围不是普通理解中的：

```text
H: 0~360
S: 0~100%
V: 0~100%
```

而通常是：

```text
H: 0~179
S: 0~255
V: 0~255
```

因此在 OpenCV 中设置 HSV 阈值时要特别小心。

## 4. 图像数据格式：HWC 与 CHW

---

## 4.1 H、W、C 分别代表什么？

在图像处理中，经常会看到：

```text
HWC
CHW
```

其中：

| 字母 | 含义            |
| ---- | --------------- |
| H    | Height，高度    |
| W    | Width，宽度     |
| C    | Channel，通道数 |

---

## 4.2 HWC 格式

### 4.2.1 什么是 HWC？

HWC 表示图像数据按照以下顺序排列：

```text
Height × Width × Channel
```

也就是：

```text
(H, W, C)
```

例如一张 480×640 的 RGB 图像：

```text
shape = (480, 640, 3)
```

表示：

```text
高度 = 480
宽度 = 640
通道数 = 3
```

---

### 4.2.2 HWC 的数据理解方式

对于 HWC 格式，访问一个像素通常是：

```python
pixel = image[y, x]
```

得到：

```text
[R, G, B]
```

或者在 OpenCV 中：

```text
[B, G, R]
```

如果访问某个通道：

```python
r = image[y, x, 0]
g = image[y, x, 1]
b = image[y, x, 2]
```

---

### 4.2.3 HWC 的应用场景

HWC 常见于：

- OpenCV
- Pillow
- NumPy 图像处理
- Matplotlib 显示
- 普通图像文件读取后的默认结构

---

### 4.2.4 为什么图像库常用 HWC？

原因是 HWC 更符合人类对图像的直观理解：

```text
先定位图像中的某个点，再查看这个点的颜色通道
```

也就是：

```text
第 y 行，第 x 列，这个像素的颜色是什么？
```

所以 HWC 更适合图像读取、显示、裁剪、绘制等操作。

---

## 4.3 CHW 格式

### 4.3.1 什么是 CHW？

CHW 表示图像数据按照以下顺序排列：

```text
Channel × Height × Width
```

也就是：

```text
(C, H, W)
```

例如一张 480×640 的 RGB 图像：

```text
shape = (3, 480, 640)
```

表示：

```text
通道数 = 3
高度 = 480
宽度 = 640
```

---

### 4.3.2 CHW 的数据理解方式

CHW 可以理解为：

```text
先分通道，再看每个通道中的二维图像
```

例如：

```text
image[0] 表示第 0 个通道
image[1] 表示第 1 个通道
image[2] 表示第 2 个通道
```

每个通道都是一个二维矩阵：

```text
image[0].shape = (H, W)
```

---

### 4.3.3 CHW 的应用场景

CHW 常见于：

- PyTorch
- 深度学习模型输入
- 卷积神经网络 CNN
- GPU 加速计算
- ONNX / TensorRT 等推理框架

---

### 4.3.4 为什么深度学习常用 CHW？

深度学习中的卷积操作通常是按通道进行计算的。

对于一张 RGB 图像，卷积核会分别作用在 R、G、B 三个通道上，再进行加权求和。

CHW 格式把通道维度放在前面，便于框架组织数据和进行高效计算。

尤其在 GPU 计算中，数据排列方式会影响内存访问效率。

---

## 4.4 HWC 与 CHW 的区别总结

| 对比项     | HWC                        | CHW                          |
| ---------- | -------------------------- | ---------------------------- |
| 维度顺序   | Height, Width, Channel     | Channel, Height, Width       |
| 常见 shape | `(H, W, C)`                | `(C, H, W)`                  |
| 常见于     | OpenCV、Pillow、NumPy      | PyTorch、深度学习框架        |
| 理解方式   | 每个位置有多个通道         | 每个通道是一张二维图         |
| 适合场景   | 图像读取、显示、裁剪、绘制 | 模型训练、模型推理、卷积计算 |

---

## 4.5 HWC 转 CHW

在 Python 中，可以使用 NumPy 转换：

```python
import numpy as np

# image: HWC 格式
image_chw = image.transpose(2, 0, 1)
```

例如：

```text
原始 shape: (480, 640, 3)
转换后:     (3, 480, 640)
```

---

## 4.6 CHW 转 HWC

```python
image_hwc = image_chw.transpose(1, 2, 0)
```

例如：

```text
原始 shape: (3, 480, 640)
转换后:     (480, 640, 3)
```

## 5. 图像坐标：为什么是像素 `(y, x)` 而不是 `(x, y)`

---

## 5.1 图像中的坐标习惯

在数学坐标系中，我们通常习惯写：

```text
(x, y)
```

其中：

- x 表示横坐标
- y 表示纵坐标

但是在图像数组中，通常使用：

```text
image[y, x]
```

也就是：

```text
先写 y，再写 x
```

---

## 5.2 为什么图像数组是 `(y, x)`？

因为图像在计算机中通常存储为二维数组。

二维数组的访问方式是：

```text
array[row, col]
```

其中：

| 数组概念 | 图像概念    |
| -------- | ----------- |
| row      | y，高度方向 |
| col      | x，宽度方向 |

所以：

```text
image[y, x] = image[row, col]
```

---

## 5.3 图像坐标方向

图像坐标系通常是：

```text
左上角为原点
x 向右增加
y 向下增加
```

示意：

```text
(0,0) -----------------> x
  |
  |
  |
  v
  y
```

---

## 5.4 示例说明

假设有一张图：

```text
shape = (480, 640, 3)
```

表示：

```text
高度 H = 480
宽度 W = 640
通道 C = 3
```

访问第 100 行、第 200 列的像素：

```python
pixel = image[100, 200]
```

这里：

```text
y = 100
x = 200
```

而不是：

```text
x = 100
y = 200
```

---

## 5.5 常见错误

很多初学者会写成：

```python
pixel = image[x, y]
```

这通常是错误的。

正确方式应该是：

```python
pixel = image[y, x]
```

尤其在裁剪图像时更要注意：

```python
crop = image[y1:y2, x1:x2]
```

而不是：

```python
crop = image[x1:x2, y1:y2]
```

## 6. 前景与背景

---

## 6.1 什么是前景？

**前景，Foreground**，通常指图像中我们关心的目标区域。

例如：

| 场景     | 前景     |
| -------- | -------- |
| 人像抠图 | 人       |
| 车牌识别 | 车牌字符 |
| 工业检测 | 缺陷区域 |
| 医学图像 | 病灶区域 |
| 文档扫描 | 文字     |

---

## 6.2 什么是背景？

**背景，Background**，通常指图像中不关心的区域，或者目标之外的区域。

例如在人像抠图中：

```text
人是前景
人后面的环境是背景
```

---

## 6.3 前景和背景不是固定的

前景和背景取决于任务目标。

例如同一张街景图：

| 任务       | 前景   | 背景             |
| ---------- | ------ | ---------------- |
| 行人检测   | 行人   | 道路、建筑、车辆 |
| 车辆检测   | 车辆   | 行人、道路、建筑 |
| 车道线检测 | 车道线 | 车辆、行人、天空 |
| 红绿灯识别 | 交通灯 | 其他所有区域     |

因此，前景和背景不是图像本身决定的，而是由任务决定的。

---

## 6.4 前景背景分离的常见方法

常见方法包括：

- 阈值分割
- 颜色分割
- 边缘检测
- 轮廓检测
- 语义分割
- 实例分割
- 背景建模
- 深度学习分割模型

## 7. 噪声

---

## 7.1 什么是噪声？

**噪声，Noise**，是图像中不希望出现的随机干扰信息。

它会影响图像质量，也会影响后续算法的准确性。

---

## 7.2 噪声的直观理解

一张干净图像应该平滑、清晰。

如果图像中出现：

- 随机白点
- 随机黑点
- 彩色斑点
- 颗粒感
- 条纹干扰

这些都可以称为噪声。

---

## 7.3 常见噪声类型

### 7.3.1 椒盐噪声

椒盐噪声表现为随机出现的黑点和白点。

类似：

```text
黑色的“椒”
白色的“盐”
```

常见原因：

- 图像传输错误
- 传感器异常
- 数据损坏

常用处理方法：

- 中值滤波

---

### 7.3.2 高斯噪声

高斯噪声是一种随机分布的噪声，通常表现为图像整体有细小颗粒感。

常见原因：

- 光照不足
- 相机传感器噪声
- 高 ISO 拍摄
- 电子信号干扰

常用处理方法：

- 均值滤波
- 高斯滤波
- 双边滤波
- 深度学习去噪

---

### 7.3.3 条纹噪声

条纹噪声表现为图像中出现固定方向的横线或竖线。

常见于：

- 扫描图像
- 工业相机
- 医学成像
- 传感器异常

---

## 7.4 为什么要去噪？

因为噪声会干扰后续处理结果。

例如：

- 边缘检测时，噪声可能被误认为边缘
- 阈值分割时，噪声可能形成错误区域
- 轮廓检测时，噪声可能产生大量小轮廓
- OCR 识别时，噪声可能影响文字识别准确率

因此，在很多图像处理流程中，去噪是非常重要的预处理步骤。

---

## 8. 平滑

---

## 8.1 什么是平滑？

**平滑，Smoothing**，是减少图像中细节变化和噪声的一种操作。

平滑通常会让图像变得更柔和，同时也可能让边缘变模糊。

---

## 8.2 平滑的直观效果

平滑前：

```text
图像中可能有很多细碎噪声和颗粒
```

平滑后：

```text
噪声减少
局部变化变小
图像变柔和
```

---

## 8.3 平滑的目的

平滑常用于：

- 降低噪声
- 减少细节干扰
- 让图像更适合后续分割
- 减少边缘检测中的误检
- 提高图像整体视觉质量

---

## 8.4 常见平滑方法

### 8.4.1 均值滤波

均值滤波会用邻域像素的平均值替代当前像素。

例如一个 3×3 区域：

```text
当前像素 = 周围 9 个像素的平均值
```

优点：

- 简单
- 速度快

缺点：

- 容易模糊边缘

---

### 8.4.2 高斯滤波

高斯滤波会根据距离中心像素的远近分配不同权重。

距离中心越近，权重越大。

优点：

- 比均值滤波更自然
- 常用于边缘检测前的预处理

缺点：

- 仍然会模糊边缘

---

### 8.4.3 中值滤波

中值滤波会用邻域像素的中位数替代当前像素。

它对椒盐噪声效果很好。

优点：

- 能有效去除黑白噪点
- 对边缘保留较好

缺点：

- 对高斯噪声不一定最优

---

### 8.4.4 双边滤波

双边滤波不仅考虑像素之间的空间距离，还考虑像素值之间的差异。

它可以在平滑图像的同时尽量保留边缘。

优点：

- 去噪同时保边缘

缺点：

- 计算量较大

---

## 9. 锐化

---

## 9.1 什么是锐化？

**锐化，Sharpening**，是增强图像边缘和细节的一种操作。

锐化会让图像看起来更清晰，但也可能放大噪声。

---

## 9.2 锐化的直观效果

锐化前：

```text
边缘不够明显
细节不够突出
图像略显模糊
```

锐化后：

```text
边缘更清楚
纹理更明显
细节更突出
```

---

## 9.3 锐化的目的

锐化常用于：

- 增强边缘
- 提升视觉清晰度
- 突出纹理细节
- 改善模糊图像
- 为后续检测增强特征

---

## 9.4 锐化的注意事项

锐化不是越强越好。

过度锐化会导致：

- 噪声被放大
- 边缘出现光晕
- 图像变得不自然
- 细节出现伪影

因此，锐化通常需要适度使用。

---

## 10. 滤波

---

## 10.1 什么是滤波？

**滤波，Filtering**，是图像处理中非常核心的操作。

滤波可以理解为：

```text
根据一定规则，重新计算每个像素的值
```

这个规则通常由一个小矩阵决定，这个小矩阵称为：

```text
卷积核 / 滤波核 / Kernel
```

---

## 10.2 滤波核是什么？

滤波核是一个小矩阵，例如：

```text
3×3 滤波核
[
  [1, 1, 1],
  [1, 1, 1],
  [1, 1, 1]
]
```

滤波时，滤波核会在图像上滑动，并与局部区域进行计算。

---

## 10.3 滤波的基本过程

对于图像中的某个像素：

1. 取该像素周围的一小块区域
2. 用滤波核和这块区域进行计算
3. 得到新的像素值
4. 移动到下一个像素继续计算

---

## 10.4 滤波的应用

滤波可以实现很多效果：

| 滤波目的 | 效果         |
| -------- | ------------ |
| 平滑滤波 | 去噪、模糊   |
| 锐化滤波 | 增强边缘     |
| 边缘检测 | 找出图像边界 |
| 纹理增强 | 突出细节     |
| 降噪处理 | 减少随机干扰 |

---

## 10.5 平滑、锐化和滤波的关系

可以这样理解：

```text
滤波是一类操作
平滑是一种滤波目的
锐化也是一种滤波目的
```

也就是说：

```text
平滑滤波：让图像更柔和
锐化滤波：让图像更清晰
```

---

## 11. 掩膜

---

## 11.1 什么是掩膜？

**掩膜，Mask**，是用于指定图像中哪些区域需要被保留、处理或忽略的一张辅助图。

掩膜通常是一张二值图。

常见取值为：

```text
0 和 255
```

或者：

```text
0 和 1
```

---

## 11.2 掩膜的直观理解

可以把掩膜理解为一张“遮罩”。

其中：

| 掩膜值   | 含义            |
| -------- | --------------- |
| 0        | 不处理 / 不保留 |
| 1 或 255 | 处理 / 保留     |

---

## 11.3 掩膜示例

原图：

```text
一张包含人和背景的图片
```

掩膜：

```text
人所在区域 = 255
背景区域 = 0
```

使用掩膜后：

```text
只保留人
背景被去掉
```

---

## 11.4 掩膜的数据形式

如果原图是：

```text
image.shape = (H, W, 3)
```

掩膜通常是：

```text
mask.shape = (H, W)
```

也就是说，掩膜只需要表示每个位置是否有效，不一定需要颜色通道。

---

## 11.5 掩膜的应用场景

掩膜常用于：

- 抠图
- 图像分割
- 目标区域提取
- 局部图像增强
- 局部模糊
- ROI 区域选择
- 背景替换
- 缺陷区域标记

---

## 11.6 掩膜与前景背景的关系

在很多任务中，掩膜用于表示前景和背景。

例如：

```text
mask = 255 的区域表示前景
mask = 0 的区域表示背景
```

也可以反过来定义，具体取决于任务约定。

---

```python
pixel = image[y, x]
```

而不是：

```python
pixel = image[x, y]
```

## 13. 初学者最容易混淆的问题

---

## 13.1 RGB 和 BGR 混淆

OpenCV 默认读取的是 BGR，而很多显示工具使用 RGB。

错误示例：

```python
import cv2
import matplotlib.pyplot as plt

img = cv2.imread("image.jpg")
plt.imshow(img)
plt.show()
```

可能会出现颜色异常。

正确写法：

```python
img = cv2.imread("image.jpg")
img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)

plt.imshow(img)
plt.show()
```

---

## 13.2 HWC 和 CHW 混淆

OpenCV 读取图像通常是：

```text
(H, W, C)
```

PyTorch 模型通常需要：

```text
(C, H, W)
```

因此送入 PyTorch 前常需要转换：

```python
image = image.transpose(2, 0, 1)
```

---

## 13.3 坐标顺序混淆

错误写法：

```python
pixel = image[x, y]
```

正确写法：

```python
pixel = image[y, x]
```

裁剪时也是：

```python
crop = image[y1:y2, x1:x2]
```

---

## 13.4 灰度图和二值图混淆

灰度图：

```text
像素值可以是 0~255 中任意值
```

二值图：

```text
像素值通常只有 0 和 255
```

二者 shape 可能一样，但含义不同。

---

## 13.5 掩膜和原图混淆

原图通常保存颜色或亮度信息。

掩膜通常保存区域选择信息。

例如：

```text
原图：这是什么颜色？
掩膜：这个位置要不要保留？
```
